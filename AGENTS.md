# TerrieFlow Client

## Назначение

TerrieFlow Client — официальное клиентское приложение VPN-сервиса TerrieFlow.

Проект находится на стадии разработки.

---

# Главные правила

Перед любыми значительными изменениями:

Сначала объясни план.

Укажи:
- затрагиваемые файлы;
- архитектурные компоненты;
- возможные риски;
- необходимость изменения документации или ADR.

Не выполняй опасные действия без подтверждения.

---

# Границы самостоятельных решений AI

Codex не должен самостоятельно:

- выбирать или менять VPN engine;
- менять security model;
- менять threat model;
- менять архитектурные принципы проекта;
- добавлять реальные API endpoints;
- добавлять production credentials;
- принимать решения, влияющие на безопасность пользователей;
- изменять архитектурные документы без предварительного review.

Такие изменения требуют:
- обсуждения;
- описания альтернатив;
- фиксации решения через ADR при необходимости.

---

# Безопасность

Запрещено:

- хранить реальные VPN-конфигурации в репозитории;
- добавлять реальные UUID пользователей;
- добавлять токены API;
- добавлять subscription URL;
- выводить чувствительные данные в логи;
- сохранять реальные production данные в fixtures, screenshots или тестах;
- самостоятельно реализовывать криптографические алгоритмы.

Использовать только synthetic mock data.

---

# Production

Этот проект НЕ имеет прямого доступа к production инфраструктуре.

Запрещено:

- подключаться к боевым серверам;
- менять Remnawave;
- менять DNS;
- менять Caddy;
- менять серверные конфигурации;
- добавлять production endpoints даже в неиспользуемые конфигурации.

---

# Разработка

Все функции сначала реализуются через:

- mock данные;
- тестовые API;
- локальные окружения.

Переход к production-интеграциям выполняется только после отдельного решения.

---

# Архитектура

Сохранять:

- разделение UI и бизнес-логики;
- направление зависимостей внутрь;
- возможность замены mock adapters на реальные реализации;
- узкие интерфейсы внешних зависимостей.

Не создавать преждевременную сложность без необходимости.

---

# Код

Приоритеты:

1. Безопасность
2. Читаемость
3. Тестируемость
4. Производительность

---

# AI Development Workflow

Перед крупными изменениями:

## Analyze

- изучить существующую архитектуру;
- определить затрагиваемые компоненты;
- проверить связанные документы.

## Plan

- описать план изменений;
- указать риски;
- определить необходимость ADR.

## Implement

- внести минимально необходимые изменения;
- не менять архитектурные границы без согласования.

## Review

- выполнить code review;
- проверить безопасность;
- проверить тесты;
- выполнить verification loop.

Не выполнять большие изменения без предварительного плана.
